# 厂内产品状态监控蓝牙网关方案

## 1. 目标与范围

本方案定义“厂内产品状态监控蓝牙网关”现场运行版本。网关的核心职责是可靠采集目标产品的 BLE 广播数据：记录每轮广播开始时间、最后广播包时间和广播结束判定时间，并稳定上传至服务器。一个房间可部署多台网关以提高发现概率；网关不判断设备在线/离线，不产生产品全局状态结论。

## 2. 交付边界

### 本期完成

- CoreS3-SE 上的 LCD、Touch、BLE、Wi-Fi、microSD 基础功能。
- 默认不区分大小写的 `SM_ICM数字`、`SM_ICD数字` 及可配置名称白名单的目标 BLE 设备扫描与过滤。
- 设备名称、MAC、地址类型、RSSI、广播数据长度的采集。
- 最多 128 台设备的本地广播生命周期管理：记录 `BROADCAST_STARTED`、最后广播包和 `BROADCAST_ENDED`；广播结束判定超时可配置，默认 40 秒。
- microSD CSV 记录广播生命周期和网关关键事件；使用持久化 Outbox 在断网后重传 MQTT 数据。
- Wi-Fi 自动连接/重连、MQTT QoS 1、广播生命周期事件和网关健康心跳稳定上报。
- 多网关场景下保留每台网关的独立观测来源；本期不做 RSSI 定位和设备全局在线/离线状态融合。
- 基础在线 OTA：HTTPS 下载、镜像校验、双分区切换、自检回滚及配置迁移；不包含远程配置下发和灰度管理平台。
- LCD 显示扫描状态、设备数量、在线数量和最近设备列表；Touch 启停扫描。
- 真实硬件上的扫描、记录、上传闭环演示与测试记录。

## 3. 硬件方案

| 项目 | 方案 | 作用 |
| --- | --- | --- |
| 主控 | M5Stack CoreS3-SE，ESP32-S3 | BLE 扫描、Wi-Fi、任务调度 |
| 交互 | 板载 LCD 与 Touch | 显示状态、扫描启停、现场诊断 |
| 本地记录 | microSD 卡，FATFS | 保存 CSV、持久化 MQTT Outbox；建议工业级 16 GiB 及以上 |
| 配置保存 | 板载 Flash/NVS | 网关 ID、安装位置、Wi-Fi 和 MQTT 参数 |
| 网络 | 2.4 GHz Wi-Fi | MQTT 上报 |
| 供电与部署 | USB-C 5 V 稳定电源、固定安装位置 | 支撑连续运行与 BLE 覆盖 |


## 4. 软件总体架构

```text
USB Serial/JTAG ──► 配置控制台 ──► NVS 配置 ──► Wi-Fi / SNTP

目标产品 BLE 广播 / Scan Response
             │
             ▼
BLE 扫描与过滤 ──► 广播生命周期管理 ──► 事件分发器 ──┬──► CSV 存储（microSD）
                                                        ├──► LCD / Touch
                                                        └──► Outbox ──► MQTT 发布 ──► Broker
                                                                              │
                                                                              ▼
                                                                  服务端采集数据存储与分析
```

模块间使用 FreeRTOS 队列传递结构化事件。NimBLE 回调只生成扫描报告，不能操作 LVGL、SD 或 MQTT；事件分发器为 CSV、UI、MQTT 分别投递副本，避免多个任务竞争读取同一队列，也避免慢速 I/O 阻塞扫描。

## 5. 模块设计

### 5.1 配置与时间模块

- 使用 Flash 的 NVS 命名空间 `gateway_cfg` 保存配置。首期配置入口固定为 ESP-IDF 原生 `esp_console`：通过 CoreS3-SE 的 USB Serial/JTAG 提供串口 REPL，受限 `cfg` 命令调用配置模块写入 NVS。每台设备烧录相同固件后通过 USB 一次性配置；LCD 只显示配置和网络状态，不承担密码输入，microSD 仅保存日志、不作为配置来源。
- `esp_console` 已提供命令注册、参数解析、行编辑和 REPL，能与 ESP-IDF 5.5.5、USB Serial/JTAG 直接集成。启用交互输入时，配置 USB 控制台为 `CONFIG_ESP_CONSOLE_USB_SERIAL_JTAG`。
- NVS 配置项如下。NVS 键名不超过 15 个字符；`gateway_id` 在部署后必须唯一。NVS 内部键 `gateway_loc` 对应 MQTT/CSV 字段 `gateway_location`，二者含义一致；`gateway_location` 和 `coverage_group` 用于服务端确定同一房间的网关覆盖组。

| 分类 | NVS 键 | 说明与示例 |
| --- | --- | --- |
| 网关身份 | `gateway_id` | 唯一标识，如 `GW-01` |
| 安装信息 | `gateway_loc` | 位置，如 `Room101-North`；对外字段名为 `gateway_location` |
| 安装信息 | `coverage_group` | 覆盖组，如 `Room101` |
| Wi-Fi | `wifi_ssid`、`wifi_password` | 厂内 2.4 GHz Wi-Fi 凭据 |
| MQTT | `mqtt_uri`、`mqtt_port` | 如 `mqtt://10.10.1.20`、`1883` |
| MQTT | `mqtt_username`、`mqtt_password`、`mqtt_qos` | 认证信息（可选）和 QoS，首期建议 QoS 1 |
| 扫描参数 | `bcast_end_s` | 广播结束判定超时，默认 `40` 秒，允许范围 `5～300` 秒 |
| 过滤规则 | `name_rules` | 可扩展名称规则；默认匹配不区分大小写的 `SM_ICM数字`、`SM_ICD数字` |
| 配置版本 | `config_ver` | 配置结构版本，用于 OTA 后新增字段默认值与受控迁移 |
| 时间 | `timezone`、`ntp_server` | 如 `Asia/Shanghai`、厂内 NTP 地址 |

- `cfg` 是白名单配置命令，不提供通用 NVS 读写 Shell。串口配置命令约定如下；`cfg commit` 校验必要字段后一次性写入 NVS，`cfg show` 必须隐藏 Wi-Fi 和 MQTT 密码。

```text
cfg set gateway_id GW-01
cfg set gateway_location Room101-North
cfg set coverage_group Room101
cfg set broadcast_end_timeout_s 60
cfg set wifi_ssid Factory-IoT
cfg set wifi_password ********
cfg set mqtt_uri mqtt://10.10.1.20
cfg set mqtt_port 1883
cfg commit
cfg show
```

- 提供 `cfg factory-reset --confirm`，仅清除 `gateway_cfg` 命名空间并恢复未配置状态；不得擦除整片 Flash 或 microSD 数据。
- 启动时读取并校验 NVS：缺少 `gateway_id` 时显示“Gateway ID 未配置”，仍允许 BLE 扫描和 SD 日志；缺少 Wi-Fi/MQTT 参数时维持本地功能、网络显示“未配置”；配置完整后依次连接 Wi-Fi、SNTP 和 MQTT。配置或网络错误不得阻塞 BLE、UI 与 CSV。
- Wi-Fi/MQTT 密码不得由 `cfg show` 回显、写入串口日志或保存至命令历史；`cfg factory-reset` 必须要求显式确认。配置控制台运行在独立任务，不得阻塞 NimBLE、UI、SD 或 MQTT。
- 不将每台设备的 ID、位置或密码写入 `sdkconfig.defaults` 或提交至仓库，避免重复编译和凭据泄露。首期通过物理 USB 串口写入；后续批量部署时增加 PC 侧串口配置脚本，按配置表逐台发送同一组 `cfg` 命令并读取 `cfg show` 结果复核。
- 后续量产或大批量预配置可使用 ESP-IDF NVS Partition Generator，根据每台设备的 CSV 参数生成独立 NVS 分区镜像并烧录；本期不采用 SoftAP/BLE 手机配网、SD 配置文件或 MQTT 远程配置，以控制交付范围和 BLE 扫描共存风险。
- 固件 OTA 不覆盖已配置的网关 ID、位置、Wi-Fi、MQTT 和广播结束超时；仅在 `config_ver` 升级且存在新增字段时写入默认值或执行受控迁移。
- 使用 SNTP 获取真实时间；校时未完成时，CSV 记录启动后的单调时间并标记时间未同步。

### 5.2 BLE 扫描与设备过滤模块

- 使用 ESP-IDF NimBLE 与 BLE-only 控制器。
- 扫描策略为 Observer-only 持续主动扫描（`BLE_HS_FOREVER`），不依赖 NimBLE 扫描超时回调；触摸停止、Host 复位或故障恢复时才停止并重新启动扫描。
- 控制器按设备地址去重，去重缓存容量为 256，刷新周期为 1 秒。这样可控制重复报告负载，并使同一广播设备约每秒有机会刷新一次最后观测时间。
- 主动扫描用于获取可能位于 Scan Response 中的设备名称。
- 解析名称、MAC、地址类型、RSSI 和原始广播数据；默认名称规则为不区分大小写的 `SM_ICM` 或 `SM_ICD` 加一位或多位十进制数字，例如 `SM_iCM2`、`SM_ICM2`。规则可由 NVS 配置扩展。
- 白名单规则数量和单条长度必须设定上限；规则解析失败时回退到默认 `SM_ICM数字`、`SM_ICD数字` 规则并记录配置错误。
- 扫描启动失败或协议栈复位时显示错误并记录日志；本期采用有限次数、固定间隔的重试策略。

### 5.3 广播生命周期管理模块

设备管理器维护“本网关观测到的广播生命周期”，不对房间内产品的全局状态下结论。目标设备具有唯一且固定的 MAC 地址，首期直接以 MAC 作为本地设备身份和 `device_id`；地址类型保留在 CSV/MQTT 中用于协议追溯，设备表容量固定为最多 128 台。

```text
首次收到本轮广播 ──► BROADCAST_STARTED ──未收到广播超过 bcast_end_s──► BROADCAST_ENDED
        ▲                        │                                              │
        └────── 新一轮首次广播 ──┴──── 每个广播包刷新 last_seen_at ───────────────┘
```

- `BROADCAST_STARTED` 的时间为本轮首次接收广播包的时间。
- 每个匹配广播包刷新 `last_seen_at`；`last_seen_at` 是本轮最后广播包时间，也是记录的广播结束时间。
- 超过 `bcast_end_s` 未收到广播后生成 `BROADCAST_ENDED`；事件生成时间 `end_detected_at` 晚于 `last_seen_at`，两者均需保留。
- `bcast_end_s` 仅在扫描器处于 `SCANNING` 时累计；用户停止扫描、扫描错误或网关维护时冻结计时，避免把“网关没有观察”误记录为广播结束。
- 正常场景的单轮广播通常持续 20～30 秒；异常场景可能频繁产生开始—结束循环，均按上述状态机逐轮记录。

设备管理器发布 `BROADCAST_STARTED`、`BROADCAST_ENDED`、`DEVICE_UPDATED` 和扫描状态事件，作为 CSV、UI、Outbox 和 MQTT 的统一输入。网关不判断设备在线/离线；`BROADCAST_ENDED` 只表示基于最后接收广播包的本地结束判定。

### 5.4 CSV 存储模块

- 使用 FATFS 挂载 microSD，在根目录 `data/` 下创建或打开当天文件 `YYYYMMDD.csv`。
- SD 卡只追加两类关键记录：广播生命周期与网关关键事件。常规 RSSI 更新、每个 BLE 广播包及 MQTT 重传均不逐条写入，避免日志膨胀。
- 本轮首次观察到设备记录 `BROADCAST_STARTED`；超过 `bcast_end_s` 未再观察到设备记录 `BROADCAST_ENDED`。频繁启停的异常广播按每一轮分别记录。
- 设备状态记录字段：

```csv
timestamp,time_synced,event_uptime_s,broadcast_started_uptime_s,last_seen_uptime_s,end_detected_uptime_s,gateway_id,gateway_location,device_id,device_name,mac,address_type,event,broadcast_started_at,last_seen_at,end_detected_at,rssi,scanner_state
```

#### CSV 设备状态记录字段

| 字段 | 含义 |
| --- | --- |
| `timestamp` | 本条 CSV 事件写入时间；已校时时使用 ISO 8601 时间，未校时时留空。 |
| `time_synced` | 是否已完成 SNTP 校时；未校时时为 `false`。 |
| `event_uptime_s` | 事件发生时本次启动后的单调运行秒数；用于未校时记录排序。 |
| `broadcast_started_uptime_s` | 本轮首次收到广播包时的单调运行秒数；未校时时用于还原开始时间。 |
| `last_seen_uptime_s` | 本轮最后收到广播包时的单调运行秒数；未校时时用于还原实际广播结束时间。 |
| `end_detected_uptime_s` | 网关生成结束判定时的单调运行秒数；仅 `BROADCAST_ENDED` 有值。 |
| `gateway_id` | 产生记录的唯一网关编号，如 `GW-01`。 |
| `gateway_location` | 网关实际安装位置，如 `Room101-North`。 |
| `device_id` | 设备稳定身份，使用唯一 MAC 地址。 |
| `device_name` | BLE 广播名称，用于现场识别和展示，如 `SM_ICM2`。不能单独作为正式唯一身份。 |
| `mac` | 本次观测到的 BLE MAC 地址。 |
| `address_type` | BLE 地址类型，仅供 BLE 协议追溯；`0` 为 Public，`1` 为 Random，不参与设备身份判定。 |
| `event` | 广播生命周期事件：`BROADCAST_STARTED`、`BROADCAST_ENDED`；网关关键事件时也可填写扫描、SD、网络或 OTA 事件类型。 |
| `broadcast_started_at` | 本轮首次实际接收到该设备 BLE 广播的时间。 |
| `last_seen_at` | 最后一次实际接收到该设备 BLE 广播的时间；作为本轮广播结束时间。未校时时留空。 |
| `end_detected_at` | 网关超时后实际生成 `BROADCAST_ENDED` 的时间；与 `last_seen_at` 区分。 |
| `rssi` | 最后一次或状态切换时的信号强度，单位 dBm。仅作诊断，不作首期定位结论。 |
| `scanner_state` | 写入事件时的扫描器状态，如 `SCANNING`、`IDLE`、`ERROR`；广播结束记录应为 `SCANNING`。 |


- 示例：

```csv
2026-08-07T10:00:22+08:00,true,15,15,15,,GW-01,Room101-North,AA:BB:CC:DD:EE:FF,SM_ICM2,AA:BB:CC:DD:EE:FF,1,BROADCAST_STARTED,2026-08-07T10:00:22+08:00,2026-08-07T10:00:22+08:00,,-55,SCANNING
2026-08-07T10:01:52+08:00,true,45,15,30,45,GW-01,Room101-North,AA:BB:CC:DD:EE:FF,SM_ICM2,AA:BB:CC:DD:EE:FF,1,BROADCAST_ENDED,2026-08-07T10:00:22+08:00,2026-08-07T10:00:52+08:00,2026-08-07T10:01:52+08:00,-70,SCANNING
```

- `device_id` 是正式设备身份，使用目标设备的唯一 MAC 地址；`address_type` 仅用于 BLE 协议追溯，不参与设备身份变更。
- `timestamp` 是本条记录写入时间，`broadcast_started_at` 是本轮首次广播时间，`last_seen_at` 是最后实际收到的广播包时间，`end_detected_at` 是结束判定生成时间；`scanner_state` 用于证明广播结束判定时网关确实处于扫描状态。未校时时，所有绝对时间留空，使用三个 `*_uptime_s` 字段还原本轮开始、最后包与结束判定的相对时间，并由 `time_synced=false` 明确标记。
- 网关关键事件至少记录：固件启动/重启、扫描开始/停止/错误、NimBLE 重置、SD 挂载或写入错误、Wi-Fi/MQTT 连接变化和 SNTP 校时成功/失败。可与设备状态写入同一当天 CSV，设备字段不适用时留空；若后续日志量增大，再拆分为 `gateway_events.csv`。
- 如现场需要排查 RSSI，可选地增加“每设备每分钟一条”的聚合观测记录（例如窗口内 RSSI 中位数、最大值和最后观测时间）；不保存逐条 BLE 广播包。
- 写入失败、SD 未挂载或剩余空间不足时，在 LCD 与串口显示错误；不影响 BLE 扫描和状态判定。
- 本期通过读卡器读取 CSV，不实现网关内日志浏览、文件轮转或自动清理。

### 5.5 Wi-Fi 与 MQTT 模块

- Wi-Fi 启动后使用 NVS 中的凭据连接厂内网络，断线后自动重连。
- MQTT 连接成功后上报广播生命周期事件 `broadcast` 和网关健康心跳 `gateway_health`；网络不可用时，待上传消息写入持久化 Outbox。
- MQTT 使用 QoS 1。网关收到 Broker `PUBACK` 后将消息视为已送达 Broker；服务端使用固定 Client ID、持久会话、QoS 1 消费，并在持久化和按 `gateway_id + event_id` 去重后完成业务处理。本期不增加服务端业务确认 Topic。
- 推荐 Topic：

```text
factory/product-status/gateway/{gateway_id}/health
factory/product-status/gateway/{gateway_id}/broadcast
```

#### MQTT 持久化 Outbox

- Outbox 与人工可读 CSV 的职责分离：CSV 用于现场追溯；Outbox 用于断网期间的可靠重传。
- Outbox 保存在 microSD 的 `outbox/` 目录，采用 256 KiB 追加式分段文件、按文件顺序发送、整段全部收到 `PUBACK` 后删除的方式；断电后允许重传尾部消息，由服务端去重。
- 默认 Outbox 上限为 256 MiB，要求 SD 卡容量至少 2 GiB，建议使用工业级 16 GiB 及以上 SD 卡。
- `BROADCAST_STARTED`、`BROADCAST_ENDED` 为高优先级，按顺序保留；`gateway_health` 只保留最新一条未发送消息。
- Outbox 满载时不得阻塞 BLE 扫描：写入 `OUTBOX_OVERFLOW` CSV 事件并在 LCD/串口告警，优先丢弃最旧的低优先级健康心跳；若仍无空间，则记录高优先级广播事件丢失告警。
- SD 未挂载时允许 MQTT 实时发送，但不提供断网重传保证，LCD 与 CSV/串口必须显示存储异常。

- `gateway_health` 由独立的 30 秒周期定时器发送，表示网关是否仍在有效扫描、网络是否可用、时间是否已同步；它不能只在状态变化时发送。
- 不上报“产品在线/离线”或“产品全局上线/离线”结论；`BROADCAST_ENDED` 仅表示该网关基于最后广播包作出的本地结束判定。服务端保存各网关的独立广播事件和健康状态，后续如需要业务状态分析由服务端另行定义。
- 每条消息包含单网关唯一的 `event_id`，格式为 `{boot_id}-{sequence}`：`boot_id` 在每次启动时随机生成，`sequence` 从 1 单调递增。服务端以 `gateway_id + event_id` 去除 QoS 1 的重复投递。
- 当 `time_synced=false` 时，`timestamp`、`broadcast_started_at`、`last_seen_at` 与 `end_detected_at` 为 `null`；服务端使用 MQTT 接收时间及三个 `*_uptime_s` 字段还原本轮相对时间。校时完成后恢复 ISO 8601 时间。建议 JSON 如下：

```json
{
```

#### MQTT `broadcast` JSON 字段

| 字段 | 含义 |
| --- | --- |
| `schema_version` | 消息格式版本，首期固定为 `1`，后续协议升级时用于兼容解析。 |
| `event_id` | 单台网关内唯一的消息编号，格式为 `{boot_id}-{sequence}`；服务端以 `gateway_id + event_id` 去重。 |
| `event_type` | 广播生命周期事件类型：`BROADCAST_STARTED` 或 `BROADCAST_ENDED`。 |
| `timestamp` | 网关生成并发送本消息的时间；未校时时为 `null`。 |
| `gateway_id` | 发送消息的唯一网关编号。 |
| `gateway_location` | 发送网关的安装位置，用于服务端确定覆盖组与观测来源。 |
| `device_id` | 设备稳定身份，使用目标设备唯一且固定的 MAC 地址，是服务端融合多网关观测的主键。 |
| `device_name` | BLE 广播设备名，用于展示和诊断。 |
| `mac` | 本网关本次观测到的 BLE MAC 地址。 |
| `address_type` | BLE 地址类型，仅供协议追溯，不参与设备身份判定。 |
| `broadcast_started_uptime_s` | 本轮首次收到广播包时的单调运行秒数；未校时时用于还原开始时间。 |
| `last_seen_uptime_s` | 本轮最后收到广播包时的单调运行秒数；未校时时用于还原实际广播结束时间。 |
| `end_detected_uptime_s` | 仅 `BROADCAST_ENDED` 有值，表示网关生成结束判定时的单调运行秒数。 |
| `broadcast_started_at` | 本轮首次接收到广播包的时间。 |
| `last_seen_at` | 本轮最后接收到广播包的时间；未校时时为 `null`。 |
| `end_detected_at` | 仅 `BROADCAST_ENDED` 必填，表示网关生成结束判定的时间。 |
| `rssi` | 最后一个广播包的 RSSI，单位 dBm。 |
| `scanner_state` | 发送事件时的扫描状态；广播结束事件应为 `SCANNING`。 |
| `time_synced` | 是否已完成 SNTP 校时；为 `false` 时，全部广播绝对时间字段为 `null`。 |
| `uptime_s` | 消息生成时本次启动后的单调运行秒数。 |

#### MQTT `gateway_health` JSON 字段

| 字段 | 含义 |
| --- | --- |
| `schema_version`、`event_id`、`timestamp`、`gateway_id`、`gateway_location` | 含义同 `broadcast` 消息。 |
| `event_type` | 固定为 `gateway_health`，表示网关健康心跳。 |
| `scanner_state` | BLE 扫描器状态，用于判断网关是否具备有效观测能力。 |
| `wifi_state` | Wi‑Fi 状态，如 `CONNECTED`、`DISCONNECTED`。 |
| `mqtt_state` | MQTT 状态，如 `CONNECTED`、`DISCONNECTED`。 |
| `time_synced` | 是否已完成 SNTP 校时；为 `false` 时，服务端应谨慎使用绝对时间。 |
| `uptime_s` | 本次启动后持续运行时间，单位秒；可辅助判断重启和运行稳定性。 |


- 服务端以 `gateway_id + event_id` 去重并保存各网关的独立 `broadcast` 事件；`gateway_health` 超过 90 秒未收到时标记该网关采集状态不健康。服务端不得将单个 `BROADCAST_ENDED` 直接解释为产品离线；是否需要形成产品业务状态，由服务端在采集数据之上另行定义。

若厂内 Broker 已支持 TLS，本期优先启用服务器证书校验；否则应明确隔离网络环境和凭据管理责任。

### 5.6 在线 OTA 模块

- 使用 ESP-IDF 双 OTA 分区：从 HTTPS Manifest 检查版本，下载到非运行分区后执行镜像完整性/SHA-256 校验、重启切换和失败回滚。
- OTA 镜像下载必须进行 TLS 服务器证书校验；首期仅允许通过 USB 串口维护命令手动检查和执行 OTA，OTA 触发、镜像来源、版本号和错误原因记录为 CSV 网关事件，并显示在 LCD 与串口。
- OTA 开始前将当前 Outbox 数据落盘，受控停止 BLE 扫描；升级成功启动后恢复配置、扫描、网络和 Outbox 重传。
- 新固件完成 NVS 配置加载、广播扫描任务启动和基础运行自检后才标记新版本有效；自检失败则回滚到上一版本。
- OTA 保留现场 NVS 配置。`config_ver` 变化时只补齐新增默认值或执行受控迁移；不通过普通 OTA 覆盖现有网关身份和网络参数。
- 首期不实现远程配置下发、自动灰度、批量任务管理或 OTA 管理平台。

### 5.7 本地 UI 与诊断模块

LCD 首页显示：BLE 扫描状态、Wi-Fi/MQTT 连接状态、本地设备总数、本轮广播中的设备数和最多四台最近设备。每行展示广播状态、名称、RSSI 和 MAC；LCD 不显示服务端融合后的全局状态。

Touch 只提供“开始扫描/停止扫描”控制。串口日志保留 NimBLE 同步、扫描启停、过滤命中、广播开始/结束、SD/Outbox、Wi-Fi/MQTT、OTA 状态和错误码，作为现场调试依据。

## 6. 任务与事件流

| 模块/任务 | 输入 | 输出 | 主要功能 |
| --- | --- | --- |
| 配置控制台 | USB Serial/JTAG、`cfg` 命令 | NVS 配置、配置状态事件 | `esp_console` 解析白名单命令、校验并写入 `gateway_cfg` |
| 配置管理 | NVS、配置变更事件 | 网关配置快照 | 向 Wi-Fi、SNTP、MQTT 提供网关身份、位置与网络参数 |
| Wi-Fi / SNTP | 网关配置、网络事件 | Wi-Fi 状态、时间同步状态 | 自动连接、重连、SNTP 校时 |
| BLE 扫描 | NimBLE GAP 回调 | 扫描报告、扫描状态事件 | 主动扫描、解析、名称过滤 |
| 广播生命周期管理 | 扫描报告、扫描状态 | 广播事件 | 最多 128 台去重、开始/结束判定 |
| 事件分发器 | 广播事件、扫描/网络/时间/OTA 事件 | CSV 队列、UI 队列、Outbox 队列 | 为多个消费者投递事件副本，隔离慢速 I/O |
| CSV 存储 | 广播事件、网关关键事件 | microSD CSV | 追加广播生命周期与诊断事件 |
| 健康心跳调度 | 网关状态、30 秒定时器 | Outbox 队列 | 生成 `gateway_health` 待发消息 |
| Outbox | 广播事件、`gateway_health`、`PUBACK` | SD 分段文件、MQTT 发布队列 | 持久化、优先级合并、断网重传和确认删除 |
| MQTT 发布 | MQTT 发布队列 | MQTT Broker | QoS 1 发布 `broadcast` 与 `gateway_health` |
| OTA | HTTPS Manifest、OTA 触发 | OTA 状态、重启/回滚事件 | 下载、校验、切换、自检与回滚 |
| UI | UI 队列、Touch 事件 | LCD / 扫描控制 | 显示广播、SD/网络/OTA 状态并启停扫描 |

### 8.3 交付验收标准

- 可在指定区域持续扫描目标产品并显示设备状态。

- CSV 可从 SD 卡导出并被常见表格工具打开。
- Wi-Fi 可连接厂内网络，MQTT Broker 可收到 `broadcast` 和 `gateway_health`；断网消息重连后可重传并被去重。
- `gateway_health` 为 30 秒周期；超过 90 秒未收到时服务端可标记网关采集状态异常。
- 每台网关可通过串口写入唯一 ID、位置、覆盖组和网络参数，重启后配置保持有效。
- 支持最多 128 台本地设备；名称白名单、广播结束超时和配置版本可通过 NVS 管理。
- 支持基础 OTA 的下载、校验、回滚和 NVS 配置保留。
- 在预留的服务端联调窗口内，服务端能够依据约定接口消费网关消息，完成至少一组多网关广播采集、来源保留和重复消息去重验证。
- 停止扫描或网络断开不造成设备状态机异常；网络断开期间 CSV 仍可记录。
- 提供固件、烧录说明、配置样例、CSV 字段说明、MQTT 接口说明和测试记录。

## 9. 本期风险与前置条件

3. 广播间隔和同房间目标设备数量分别是多少？设备名称是否位于广播包或仅位于 Scan Response？本地设备表上限暂定 128 台是否满足现场需求？
4. 单网关覆盖范围及多网关安装位置、网关 ID、位置与覆盖组命名规则如何定义？是否需要根据现场对比决定主动或被动扫描？


### 10.2 广播生命周期与采集边界

1. 网关维护广播生命周期状态机，用于 LCD、CSV、MQTT 和单网关现场诊断；事件命名固定为 `BROADCAST_STARTED`、`BROADCAST_ENDED`。
2. 服务端保存各网关的独立广播采集数据；`gateway_health` 超过 90 秒未收到时可标记该网关采集状态异常，但不据此生成设备在线/离线结论。
3. 网关 MQTT 发送 `broadcast` 与 `gateway_health`，不发送设备在线/离线或全局状态结论；单网关 `BROADCAST_ENDED` 不能直接解释为产品离线。
4. 广播结束阈值为可配置的 `bcast_end_s`，默认 40 秒；停扫、扫描错误或网关维护时冻结广播结束计时。Wi-Fi/MQTT 中断不影响本地扫描、CSV 与 Outbox 记录。

### 10.3 microSD 与 CSV 数据

1. 确认 SD 卡记录数据，并通过读卡器导出；在 SD 卡根目录创建 `data/` 保存 CSV，从而不开发上位机导出工具。
2. 确认文件组织：建议按天创建 `data/YYYYMMDD.csv`，当天文件追加写入；需要确认跨日、重启和文件名冲突的处理规则。
3. 确认最小设备记录字段：`timestamp`、`time_synced`、`event_uptime_s`、`broadcast_started_uptime_s`、`last_seen_uptime_s`、`end_detected_uptime_s`、`gateway_id`、`gateway_location`、`device_id`、`device_name`、`mac`、`address_type`、`event`、`broadcast_started_at`、`last_seen_at`、`end_detected_at`、`rssi`、`scanner_state`。
4. 本期固定记录 `BROADCAST_STARTED`、`BROADCAST_ENDED` 及网关关键事件；不记录逐条广播、常规 RSSI 更新或 MQTT 重传。
5. 确认 CSV 与 Outbox 的目录、编码、分段文件大小、容量上限、保留周期、SD 满和写入失败处理方式。

### 10.4 云端接口与融合规则

1. 确认 MQTT Broker 地址、端口、TLS 要求、认证方式、Topic 命名和 QoS。
2. 固定上报两类消息：`broadcast` 与 `gateway_health`；确认第 5.5 节 JSON 字段、Topic、频率和 QoS。
3. 固定事件唯一性与去重规则：`event_id={boot_id}-{sequence}`，服务端以 `gateway_id + event_id` 去重；确认 `boot_id` 随机数长度与服务端字段类型。
4. 确认服务端融合窗口：设备观测 60 秒、网关健康 90 秒；多网关重复观测保留来源，本期不以 RSSI 做定位结论。
5. 固定断网策略：SD Outbox 持久化、QoS 1、Broker `PUBACK` 后删除、重连顺序重传；服务端使用持久会话并按 `gateway_id + event_id` 去重。
