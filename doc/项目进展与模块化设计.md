# BLEGateway 项目进展与模块设计

## 1. 项目定位

本项目面向 M5Stack CoreS3-SE（ESP32-S3），使用 ESP-IDF v5.5.5 和 M5Stack CoreS3 BSP，逐步构建 BLE Gateway。当前阶段聚焦于“无硬件可持续开发”：完成 BLE 主动扫描、目标设备过滤、设备生命周期管理和 LCD/Touch 验证入口；暂不实现 SD 存储、MQTT 或完整业务协议解析。

## 2. 当前进展

已完成的功能包括：

- ESP32-S3、16 MiB Flash、CoreS3 BSP 和自定义分区表配置。
- NimBLE BLE-only 配置，持续主动扫描；控制器按地址去重并每秒刷新缓存。
- 从广播包或 Scan Response 解析设备名称，仅接受 `ICD*` / `ICM*`。
- 扫描报告包含名称、MAC、地址类型、RSSI 和原始广播数据。
- 设备按 MAC 与地址类型去重，支持新增、更新、在线、离线和重新在线。
- 只有扫描处于 `Scanning` 状态时才推进离线计时；停止扫描或扫描错误时冻结观察时间。
- LCD 显示扫描状态、设备数量、在线数量和最多四台设备；Touch 控制扫描启停。
- 主机侧测试覆盖过滤器、设备状态核心和设备列表模型。

当前限制：尚未在真实 CoreS3-SE 上烧录验证，尚未接入 Wi-Fi、MQTT、SD 和设备业务协议。

## 3. 模块设计

### 3.1 应用入口

[main/app/app_main.c](../main/app/app_main.c) 的 `app_main()` 只负责启动顺序：NVS 初始化 → BLE 扫描器初始化 → 设备管理器初始化 → UI 初始化。入口不直接处理广播或 LVGL，便于后续替换为正式应用入口。

### 3.2 BLE 扫描器

[main/ble/ble_scanner.c](../main/ble/ble_scanner.c) 的 `ble_scanner_init()` 创建扫描事件队列、初始化 NimBLE 并启动主机任务。`scanner_on_sync()` 获取本机地址类型并启动扫描；`scanner_start_continuous()` 配置持续主动扫描；`scanner_gap_event()` 解析广播、过滤名称并发布报告。`ble_scanner_start()` 和 `ble_scanner_stop()` 供 Touch 控制。

### 3.3 广播数据与名称过滤

[main/ble/ble_types.h](../main/ble/ble_types.h) 定义跨模块共享的 `ble_scan_report_t`。 [main/ble/device_filter.c](../main/ble/device_filter.c) 的 `device_filter_copy_name()` 负责安全拷贝并截断名称，`device_filter_name_matches()` 只匹配 `ICD` 和 `ICM` 前缀。该模块不依赖 NimBLE，可在主机上单独测试。

### 3.4 设备管理器

[main/device/device_manager.c](../main/device/device_manager.c) 是扫描器与 UI/未来 MQTT 之间的边界。它消费扫描器队列，不让 UI 直接接触 NimBLE 事件。设备管理任务维护输出队列，并发布设备新增、更新、重新在线、离线和扫描状态事件。

[main/device/device_manager_core.c](../main/device/device_manager_core.c) 是无 RTOS 的设备表核心：`device_registry_process_report()` 按 MAC+地址类型去重，`device_registry_mark_next_offline()` 执行 60 秒超时判定，`device_observation_clock_*()` 只累计有效扫描时间并处理 32 位计时回绕。

### 3.5 设备列表模型与 UI

[main/device/device_list_model.c](../main/device/device_list_model.c) 将设备管理事件转换为 UI 可消费的数据模型，统计设备总数/在线数，并按“在线优先、最近发现优先”排序。[main/app/app_ui.c](../main/app/app_ui.c) 通过 `app_ui_task()` 消费设备管理队列，在 `bsp_display_lock()` 保护下更新 LVGL；`update_device_list()` 渲染四行设备信息。`scanner_toggle_cb()` 处理 Touch 启停。

## 4. 关键设计点

1. **单向队列边界**：NimBLE → `ble_scanner` 队列 → `device_manager` → UI/未来 MQTT，避免多个消费者竞争同一队列。
2. **线程隔离**：NimBLE 主机任务不调用 LVGL；所有界面更新只发生在 UI 任务并持有 BSP 显示锁。
3. **稳定数据结构**：`ble_scan_report_t` 和 `managed_device_t` 是后续设备管理、MQTT、存储模块的共享接口。
4. **观察时间而非墙上时间**：停止扫描期间不累计离线时间，避免把本机停止观察误判成设备离线。
5. **有限资源策略**：设备表最多 16 台，事件队列满或设备表满时非阻塞丢弃并输出日志。
6. **纯逻辑可测试**：过滤器、状态核心和列表模型不依赖硬件；测试入口为 `./tests/run_host_tests.sh`。

## 5. 以 `app_main()` 为入口的模块级流程

1. **NVS 初始化** — 文件：`main/app/app_main.c`；函数：`app_main()`、`nvs_flash_init()`。必要时擦除并重新初始化 NVS。
2. **创建 BLE 扫描基础设施** — 文件：`main/ble/ble_scanner.c`；函数：`ble_scanner_init()`。创建事件队列，初始化 NimBLE，注册 `scanner_on_sync()` / `scanner_on_reset()`，启动 `scanner_host_task()`。
3. **NimBLE 主机同步** — 文件：`main/ble/ble_scanner.c`；函数：`scanner_on_sync()`。推断本机地址类型并调用 `scanner_start_continuous()`。
4. **启动主动扫描** — 文件：`main/ble/ble_scanner.c`；函数：`scanner_start_continuous()`。以 `BLE_HS_FOREVER` 持续扫描，发布 `SCANNING` 状态。
5. **处理广播事件** — 文件：`main/ble/ble_scanner.c`；函数：`scanner_gap_event()`。解析广播/Scan Response，调用 `device_filter_copy_name()` 和 `device_filter_name_matches()`。
6. **发布匹配报告** — 文件：`main/ble/ble_scanner.c`；结构：`ble_scan_report_t`。填充名称、地址、RSSI、长度和原始广播数据，写入 BLE 事件队列。
7. **启动设备管理器** — 文件：`main/app/app_main.c`、`main/device/device_manager.c`；函数：`device_manager_init()`、`device_manager_task()`。消费 BLE 队列，更新观察时钟和设备注册表。
8. **维护设备生命周期** — 文件：`main/device/device_manager_core.c`；函数：`device_registry_process_report()`、`device_registry_mark_next_offline()`。产生新增、更新、在线和离线事件。
9. **发布管理事件** — 文件：`main/device/device_manager.c`；函数：`manager_publish()`、`manager_publish_scanner_state()`。将设备事件写入管理器输出队列。
10. **初始化 LCD/Touch/LVGL** — 文件：`main/app/app_ui.c`；函数：`app_ui_start()`。创建标题、状态、数量标签、四行设备列表和扫描按钮。
11. **消费管理事件并刷新列表** — 文件：`main/app/app_ui.c`、`main/device/device_list_model.c`；函数：`app_ui_task()`、`device_list_model_apply()`、`update_device_list()`。在显示锁内更新状态和设备列表。
12. **持续扫描与 Touch 控制** — 文件：`main/ble/ble_scanner.c`、`main/app/app_ui.c`；函数：`scanner_gap_event()`、`scanner_toggle_cb()`。Touch 可停止或重新启动扫描；异常结束时扫描器尝试恢复持续扫描。
